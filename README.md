# Level-Controllable Chinese Code Explanation Generation

This repository provides the dataset, training/evaluation code, and experimental results for the paper *"Controllable Chinese Code Explanation Generation via Multi-Level Joint Fine-Tuning"* (submitted to Computer Applications in Engineering Education, CAEE).

## Overview

We address controllable code explanation generation: producing differentiated Chinese explanations of Python code conditioned on learner level (beginner / intermediate / expert), using a single fine-tuned model rather than per-level specialists. Full method and results are described in the paper; this repository supports reproducibility.

## Repository structure

```
data/
├── train_750.json      750 annotated training samples (250 per level), generated by Qwen2.5-7B-Instruct
└── test_150.json        150 held-out test samples (50 per level)

code/
├── train_multilevel_v2.py       Main training script (multilevel + specialist, LoRA r=8/alpha=16, QLoRA)
├── eval_batch.py                 Main evaluation script (batch inference)
├── evaluate_multilevel_v2.py     Earlier evaluation script (superseded by eval_batch.py)
├── run_bertscore.py              BERTScore (bert-base-chinese) computation for the main models (multilevel/specialist/zero-shot/few-shot); output path is a local AutoDL path in the script and the resulting JSON was not uploaded to this repository (see Data quality notes)
├── step_multi_seed.py            Two-step generation, seed-robustness experiment for seeds {0,1,2} (in addition to an existing seed=42 run); this is a separate ablation from the seed={42,123,456} stability check referenced in the paper's Section 4.5 (see Data quality notes)
├── task9_specialist_750.py       750-sample specialist training (data-volume-matched ablation)
└── task9_run_one.py              Single (level, seed) training job entry point

results/
├── results_v3/                   Main results underlying Table 1/2 (produced by eval_batch.py)
├── rework_phase1_2/               Unified 47-term Technical Density (TD) metric + supplementary experiments
│   └── td_metric.py               TD metric implementation (47-term canonical vocabulary)
├── task9_specialist750/           750-sample specialist cross-level evaluation (Table 4 source)
└── ctrl_po_twostep_bertscore/     BERTScore for CTRL-PO / Two-step baselines (Table 1 source)
```

Model weights (LoRA adapters) are not included; they can be reproduced from the training script and dataset, or requested from the authors.

## Dataset

`data/train_750.json` and `data/test_150.json` each contain records with the following fields:

- `instruction`: the level-conditioned prompt (includes the source code)
- `output`: the annotated Chinese explanation
- `raw_code` / `original_code`: the source Python function
- `func_name`, `original_docstring`: metadata from the source (CodeSearchNet Python subset)
- `meta.level`: one of `beginner`, `intermediate`, `expert`

Annotations were generated by Qwen2.5-7B-Instruct and spot-checked by human review (30-sample audit, 100% qualification rate; see paper Section 4.1).

## Data quality notes (disclosed for transparency)

- An earlier evaluation artifact (`results_v3/ctrl_baseline.json`) contained a 3x duplication bug (50 unique records exported 3 times); this was identified, deduplicated, and corrected before the numbers reported in the paper were computed. Left in this repository as the original generation record for auditability.
- The significance test in `results/rework_phase1_2/phase1_final.json` (`.stats.ctrl_baseline`) was originally computed on the undeduplicated 150-row-per-level `ctrl_baseline` data, which violates the independence assumption of the Mann-Whitney U test (the reported U=5508 for beginner-vs-intermediate exceeds the n=50 theoretical maximum of 2500). This has been recomputed on the deduplicated 50-per-level set; see `results/rework_phase1_2/ctrl_baseline_dedup_stats.json`. All three pairwise comparisons remain significant after Bonferroni correction, so the paper's conclusions on layer-wise TD separation are unaffected — this note only corrects the supporting statistic.
- A historical draft number (TD = 0.012 for specialist_expert's intermediate-level output) was traced to a manuscript revision error, not a computed result; the correct value (0.088, consistent with `results/rework_phase1_2/phase1_final.json`) is what is reported in the final paper.
- Early manuscript drafts of Table 1 carried BERTScore values for the multilevel model (0.762/0.792/0.804 for beginner/intermediate/expert) that were traced to a manuscript revision error and were not backed by any computed output in this repository; the final paper reports the computed values (0.7302/0.7917/0.8042; macro-average 0.7754) from `results/bertscore_results.json`, which are consistent with the per-sample records in `results/results_v3/*.json`.
- The `td` field in `results/results_v3/*.json` and `results/ctrl_po_twostep_bertscore/*.json` uses an earlier, uncurated term list (e.g. `ctrl_baseline` TD ≈ 1.355 for a beginner-level sample) and does **not** match the TD numbers reported in the paper. The paper's TD numbers (and the unified 47-term canonical vocabulary) are computed in `results/rework_phase1_2/phase1_final.json` / `td_metric.py`; treat any `td` field elsewhere in this repository as a historical/intermediate value, not the reported result.
